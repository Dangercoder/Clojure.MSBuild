# Clojure.MSBuild

[![Clojure.MSBuild](https://img.shields.io/nuget/v/Clojure.MSBuild.svg?label=Clojure.MSBuild)](https://www.nuget.org/packages/Clojure.MSBuild/)
[![Clojure.MSBuild.TestAdapter](https://img.shields.io/nuget/v/Clojure.MSBuild.TestAdapter.svg?label=TestAdapter)](https://www.nuget.org/packages/Clojure.MSBuild.TestAdapter/)
[![Clojure.MSBuild.Templates](https://img.shields.io/nuget/v/Clojure.MSBuild.Templates.svg?label=Templates)](https://www.nuget.org/packages/Clojure.MSBuild.Templates/)

MSBuild integration for ClojureCLR. Build, test, and run Clojure on .NET with standard `dotnet` commands.
No non-dotnet tools needed.

`dotnet build` AOT-compiles your namespaces and produces a standalone assembly whose entry point is a
`gen-class` `Main` calling your `-main`. No C# in your project, no `.cljr` files needed at runtime.

## Requirements

- .NET 11.0 SDK, 11.0.100 or later
- ClojureCLR 1.13.0-alpha8 or later (the TestAdapter is compiled against it)
- git, only for Clojure dependencies from git

## Quick Start with templates

```bash
dotnet new install Clojure.MSBuild.Templates
dotnet new clojure-clr-minimal-api -n orders --root-namespace danger.se
cd orders
dotnet build
dotnet test
dotnet run
```

| Template | Short name | Contents |
|----------|------------|----------|
| Console application | `clojure-clr-console` | `-main`, ready for `dotnet run` |
| Minimal API | `clojure-clr-minimal-api` | ASP.NET Core minimal API, SQLite, HoneySQL, clojure.spec domain model with spec-driven property tests, OpenTelemetry, an nREPL server inside the app in Debug, Dockerfile and docker-compose with the Aspire dashboard, end-to-end tests |

`--root-namespace` sets the root of the generated Clojure namespaces (`danger.se.server`,
`danger.se.routes`, ...). It defaults to the project name in lower case (`-n my-api` gives
`my-api.server` in `src/my_api/`). The templates live in
[`templates/`](templates/) and `scripts/smoke-templates.sh` generates, builds, tests and runs both.

## Quick Start by hand

### 1. Create a project

```bash
dotnet new console -n MyApp
cd MyApp
rm Program.cs
```

The project must not contain C# sources: `dotnet build` replaces the project assembly with the
compiled Clojure entry point (see [How the build works](docs/how-it-works.md)).

### 2. Add packages

```bash
dotnet add package Clojure.MSBuild
dotnet add package Clojure --version 1.13.0-alpha8
```

### 3. Update your .csproj

```xml
<Project Sdk="Microsoft.NET.Sdk">

  <PropertyGroup>
    <OutputType>Exe</OutputType>
    <TargetFramework>net11.0</TargetFramework>
    <ClojureMainNamespace>app</ClojureMainNamespace>
    <CopyLocalLockFileAssemblies>true</CopyLocalLockFileAssemblies>
  </PropertyGroup>

  <ItemGroup>
    <PackageReference Include="Clojure.MSBuild" Version="0.0.11" />
    <PackageReference Include="Clojure" Version="1.13.0-alpha8" />
  </ItemGroup>

  <ItemGroup>
    <!-- optional: the compiled output does not need the sources, but the REPL can reload them -->
    <Content Include="src/**/*.cljr" CopyToOutputDirectory="PreserveNewest" />
  </ItemGroup>

</Project>
```

Clojure.MSBuild turns on `EnablePreviewFeatures`, which ClojureCLR's runtime for `net11.0` needs
(it is marked as using runtime async).

### 4. Write your app

Create `src/app.cljr`:

```clojure
(ns app)

(defn -main [& args]
  (println "Hello from ClojureCLR!"))
```

### 5. Build and run it

```bash
dotnet build
dotnet run
```

`dotnet build` compiles `app` (and every namespace it requires) to `.dll` files next to
`MyApp.dll`, and `MyApp.dll` itself is the compiled entry point: a class named after the
assembly with a static `Main` generated by `gen-class` that calls `app/-main`.
`dotnet MyApp.dll`, `./MyApp` and `dotnet publish` all use it.

A compile error fails the build and is reported at its source line, so IDEs list it like a
C# error:

```
src/app.cljr(4,3): error CLJ0001: compiling app: Unable to resolve symbol: prnitln in this context
```

How the two compiled layers, the shared runtime cache and ReadyToRun work is described in
[docs/how-it-works.md](docs/how-it-works.md).

Because the project assembly is replaced, the project cannot contain C# sources of its own
and `AssemblyName` must be a valid .NET type name (letters, digits, `_` and `.`; the
templates take care of that). Put C# in a class library and reference it, or set
`ClojureEntryPoint` to `csharp` to keep a generated C# `Main` as the entry point; Clojure
is still AOT-compiled and the tooling works the same way.

`dotnet publish` works framework-dependent and self-contained. `PublishSingleFile`,
`PublishTrimmed` and `PublishAot` cannot work with code that Clojure loads at runtime, and
fail the build with an error saying so.

## Clojure Dependencies

Add Clojure libraries from git directly in your `.csproj` — no `deps.edn` needed:

```xml
<ItemGroup>
  <!-- .NET deps from NuGet -->
  <PackageReference Include="Clojure" Version="1.13.0-alpha8" />
  <PackageReference Include="Microsoft.Data.Sqlite" Version="11.0.0" />

  <!-- Clojure deps from git -->
  <ClojureGitDep Include="io.github.clojure/clr.data.json" Tag="v2.5.1" Sha="f84cb88" />
  <ClojureGitDep Include="com.github.seancorfield/honeysql" Tag="v2.7.1368" Sha="b8332fc" />
</ItemGroup>
```

Repos are cloned to `~/.gitlibs` (cached, compatible with `cljr` and the JVM tools; `GITLIBS`
moves it) when the build and tooling run; the compiled application contains the dependency
namespaces and does not need git at runtime. `io.github`, `com.github`, `io.gitlab`,
`com.gitlab`, `org.bitbucket` and `ht.sr` names resolve to their URL; otherwise give one:

```xml
<ClojureGitDep Include="my/lib" Tag="v1.0" Sha="abc1234" Url="https://example.com/repo.git" />
<!-- a library in a subdirectory of its repository (:deps/root) -->
<ClojureGitDep Include="my/mono-lib" Sha="abc1234" Url="https://example.com/mono.git" Root="libs/core" />
<!-- a library on disk, relative to the project (:local/root) -->
<ClojureGitDep Include="my/local-lib" LocalRoot="../local-lib" />
```

With both `Tag` and `Sha`, the tag must point at the commit. A `deps-clr.edn` or `deps.edn`
in the project is read too (both sources merge), with the same coordinates
(`:git/url`/`:git/sha`/`:git/tag`/`:deps/root`, `:local/root`). Dependencies of
dependencies are resolved from their own `deps-clr.edn`/`deps.edn`; when two ask for the same
library, the first one seen wins (the project's own come first) and a warning names the
other. Maven coordinates (`:mvn/version`) cannot be used on the CLR and are skipped with a
warning: reference the library's NuGet package instead. `ClojureDepsAliases` selects
`deps.edn` aliases whose `:extra-deps` and `:extra-paths` are used:

```xml
<ClojureDepsAliases>dev;test</ClojureDepsAliases>
```

A dependency that cannot be resolved (a typo in a tag, an unknown SHA, no network for a
repository that is not cached yet) fails the build with `error CLJ0002` naming it. Parallel
builds that share `~/.gitlibs` take turns cloning the same repository.

## Testing

Add the test adapter package:

```bash
dotnet add package Clojure.MSBuild.TestAdapter
dotnet add package Microsoft.NET.Test.Sdk
```

Add test content to your .csproj:

```xml
<Content Include="test/**/*.cljr" CopyToOutputDirectory="PreserveNewest" />
```

Create test files with the `_test.cljr` suffix in a `test/` directory (`ClojureTestDir` and
`ClojureTestSuffix` change both):

```clojure
(ns app-test
  (:require [clojure.test :refer [deftest is testing]]))

(deftest test-addition
  (testing "math works"
    (is (= 4 (+ 2 2)))))
```

Run tests:

```bash
dotnet test
```

Every `deftest` and `defspec` in `test/**/*_test.cljr` (`.cljc`, `.clj`) is discovered and
reported individually, so `dotnet test --filter` and IDE test explorers work as with any other
.NET test project. Discovery reads the files with the Clojure reader: tests in `(comment ...)`
and `#_` forms are left out, and qualified forms (`t/deftest`) are found. Tests that a macro
defines are reported when the whole project runs. A failed test shows every failing assertion
with its `testing` context, expected and actual value; an error shows the exception, its
`ex-data` and stack trace; both point at the test's source line. What a test prints is
attached to its result, and a test namespace that does not compile fails its tests with the
compiler error.

"Debug Test" in Visual Studio and Rider starts the tests under the debugger. Cancelling a run
stops the test process. A run settings file can stop a run that takes too long (the
remaining tests fail with a message saying so); `CLOJURE_MSBUILD_TEST_TIMEOUT=<seconds>` does
the same without one. Environment variables from the run settings reach the tests.

```xml
<RunSettings>
  <ClojureTest>
    <TimeoutSeconds>300</TimeoutSeconds>
  </ClojureTest>
</RunSettings>
```

Without VSTest, the tests run faster and print clojure.test's report:

```bash
dotnet msbuild /t:clj-test
dotnet msbuild /t:clj-test -p:ClojureTests="app-test app-test/test-addition"
```

Watch mode runs the tests, then keeps the process running and, whenever you save a file,
reloads the namespaces that changed and the ones that depend on them, and runs only the
tests that depend on the change (a test file on its own reruns in milliseconds):

```bash
dotnet run -- --clj-mode test-watch
# or
dotnet msbuild /t:clj-test-watch
```

## nREPL

```bash
dotnet add package clojure.tools.nrepl --prerelease
dotnet msbuild /t:clj-nrepl
# or
dotnet run -- --clj-mode nrepl
```

The server listens on 127.0.0.1 and ::1, port 1667 (`-p:ClojureNReplPort=7888` picks
another, `0` any free one; if 1667 is taken a free port is used), and writes the port to
`.nrepl-port` in the project directory, where Calva, CIDER and other clients look for it. The
file is removed when the server stops (Ctrl-C). The server is precompiled into the library
layer, so it is up in about two seconds.

### nREPL inside the running application

To evaluate code in the running application (the web server with its state, rather than a
separate process), let the application start the server next to its `-main`, for example in
Debug builds only:

```xml
<ClojureNReplInApp Condition="'$(Configuration)' == 'Debug'">true</ClojureNReplInApp>
```

`dotnet run` then prints `nREPL server started on port ...` and writes `.nrepl-port`. The
project's sources are on the load path, so you can reload edited namespaces from your editor.
`CLOJURE_MSBUILD_NREPL` overrides the build for one run: `off` turns the server off, `on` turns
it on, a number picks the port. The minimal API template does this in Debug.

### Middleware

`ClojureNReplMiddleware` adds middleware to clojure.tools.nrepl's default set: qualified
symbols of vars, separated by `;`, each holding one middleware or a collection of them (the
namespaces are required first):

```xml
<ClojureNReplMiddleware>my.nrepl/wrap-info;other.lib/middleware</ClojureNReplMiddleware>
```

## Development mode

```bash
dotnet msbuild /t:clj-dev
# or
dotnet run -- --clj-mode dev
```

runs the application and, whenever you save a Clojure file, reloads the namespaces that
changed, and the loaded ones that depend on them, into the running process. Code that reaches
functions through vars sees the new definitions at once: pass `#'handler` rather than
`handler` to a server, or call functions by name when a request comes in. With
`ClojureNReplInApp` on, the nREPL server runs in the same process (`--clj-mode dev 7888` picks
its port). `-p:ClojureRunArgs="..."` passes arguments to `-main`.

## Run a Script

```bash
dotnet msbuild /t:clj-run -p:ClojureScript=path/to/script.cljr -p:ClojureScriptArgs="one two"
```

The arguments are in `*command-line-args*`. (`-p:File=` still works.)

## AOT Compilation

The main namespace and everything it requires are compiled when they change. To compile
additional namespaces (for example ones with their own `gen-class`, or ones the application
loads by name at runtime), list them:

```xml
<PropertyGroup>
  <ClojureNamespacesToCompile>my.lib;my.utils</ClojureNamespacesToCompile>
</PropertyGroup>
<!-- or -->
<ItemGroup>
  <ClojureCompile Include="my.lib;my.utils" />
</ItemGroup>
```

Note: `(t/await (f ...))` on a call to a Clojure `^:async` function needs the call's static
`Task<T>` type. Tag the call site, or attach the tag to the var (a return tag on a `^:async`
`defn` is not kept on the var):

```clojure
(alter-meta! #'execute! assoc :tag (symbol "System.Threading.Tasks.Task`1[System.Object]"))
```

## Multi-targeting

With `TargetFrameworks`, every framework is built and compiled. `dotnet msbuild /t:clj-test`
(and the other `clj-*` targets) run for the first framework in the list, or for
`-p:ClojureTargetFramework=net11.0`.

## Configuration

| Property | Description | Default |
|----------|-------------|---------|
| `ClojureMainNamespace` | Namespace with `-main` function | _(required)_ |
| `ClojureEntryPoint` | `gen-class` (compiled entry point replaces the project assembly) or `csharp` (generated C# `Main`, allows C# sources in the project) | `gen-class` |
| `ClojureSourceDir` | Source directory | `src` |
| `ClojureExtraSourceDirs` | Additional source dirs, separated by `;` or `\|` (or `ClojureSource` items) | |
| `ClojureNamespacesToCompile` | Additional namespaces to compile, separated by `;` (or `ClojureCompile` items) | |
| `ClojureTestDir` | Test directory | `test` |
| `ClojureTestSuffix` | Suffix of test file names | `_test` |
| `ClojureTests` | Namespaces and `ns/name` tests for `clj-test` (separated by spaces or `;`) | all |
| `ClojureDepsAliases` | `deps.edn` aliases whose `:extra-deps`/`:extra-paths` are used (separated by `;`) | |
| `ClojureAutoLoadAssemblies` | Load every assembly next to the application at startup; `false` leaves it to the application (`assembly-load`). Tooling always loads them | `true` |
| `ClojureLibCacheDir` | Machine-wide cache of the precompiled Clojure runtime shared between projects | `~/.clojure-msbuild/lib-cache/` |
| `ClojureLibCache` | Set to `false` to disable the shared cache | `true` |
| `ClojureReadyToRun` | Compile the library layer and `Clojure.dll` to native code with crossgen2 | `true` |
| `ClojureNReplPort` | Port of `clj-nrepl`, `clj-dev` and the in-app server (`0` = any free port) | `1667` |
| `ClojureNReplInApp` | Start an nREPL server inside the application | `false` |
| `ClojureNReplMiddleware` | Extra nREPL middleware (qualified var symbols, separated by `;`) | |
| `ClojureScript`, `ClojureScriptArgs` | Script and arguments for `clj-run` | |
| `ClojureRunArgs` | Arguments to `-main` for `clj-dev` | |
| `ClojureTargetFramework` | Framework the `clj-*` targets use in a multi-targeted project | first |

## Developing Clojure.MSBuild

- `scripts/test.sh` runs the unit tests of the tooling ([`tests/Clojure.MSBuild.Tests`](tests/Clojure.MSBuild.Tests)),
  built with the targets in this repository
- `scripts/lint.sh` lints the Clojure sources with clj-kondo
- `scripts/pack.sh` packs Clojure.MSBuild, Clojure.MSBuild.TestAdapter and
  Clojure.MSBuild.Templates into `packages/`
- `scripts/smoke-templates.sh` verifies the templates end to end against freshly packed packages
- `scripts/set-version.sh 0.1.0` sets the version of all three packages (`version.props`) and of
  the package references in the templates, the examples and this README
- `NUGET_API_KEY=... scripts/release.sh` runs the unit tests, packs and pushes all three to nuget.org

The scripts use `dotnet` from the `PATH`; set `DOTNET` to use another.
